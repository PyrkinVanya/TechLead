Фундаментальная разница между senior-разработчиком и tech lead именно в широте кругозора за пределами 1С. Вот подробный разбор областей, которые вы должны понимать как архитектор и лидер команды.

1. Инфраструктура и Системное администрирование (Уровень понимания, а не выполнения)
Вы должны знать достаточно, чтобы общаться с сисадминами, проектировать отказоустойчивые решения и понимать, где "узкое горло" системы.

Операционные системы: Основы администрирования Windows Server и Linux (популярен для серверов 1С на PostgreSQL). Понимание: службы, планировщик задач, мониторинг ресурсов (CPU, RAM, Disk I/O), ограничения прав.

Сети (Networking):

Базовые понятия: TCP/IP, DNS, Firewall, порты, VPN. Почему не работает обмен между серверами? Вы должны уметь задать правильные вопросы сетевику.

Термины для планирования: Латентность, пропускная способность. Критично для распределенных систем и тонких клиентов.

Виртуализация и облака: Понимание принципов VMware, Hyper-V, KVM. Знание основных облачных платформ (Yandex Cloud, Selectel, SberCloud/AWS analogs). Как развернуть кластер 1С в облаке? Какие сервисы (объектное хранилище, managed БД) можно использовать?

Резервное копирование и аварийное восстановление (Backup/DR): Вы должны спроектировать и проконтролировать стратегию бэкапов не только данных 1С, но и всей инфраструктуры. Знать RPO (целевая точка восстановления) и RTO (целевое время восстановления).

2. Базы данных (Уровень уверенного пользователя и проектировщика)
Здесь недостаточно просто писать запросы. Нужно понимать, как работает СУБД "под капотом".

Глубокая работа с MS SQL Server / PostgreSQL:

Индексы: Типы индексов (clustered, non-clustered, покрывающие), когда и какой создавать. Анализ планов выполнения запросов (Execution Plan).

Блокировки и транзакции: Уровни изоляции, deadlock-и, как их выявлять и предотвращать. Прямая связь с "зависаниями" в 1С.

Производительность: Мониторинг медленных запросов, использование Profiler или расширенных событий. Умение сказать разработчику не просто "запрос тормозит", а "проблема в отсутствии индекса по полю в условии WHERE, что приводит к table scan на 10 млн записей".

Администрирование: Понимание задач обслуживания (обновление статистики, перестроение индексов), настройки файлов данных и логов.

3. DevOps и Инструменты разработки (Уровень внедрения и контроля)
Это основа современной инженерной культуры.

Системы контроля версий (VCS): Git — это стандарт. Вы должны понимать branching strategies (GitFlow, trunk-based), уметь проводить code review не в конфигураторе, а в GitLab/GitHub, разрешать конфликты слияния. Ваша команда должна хранить конфигурацию в git.

CI/CD (Непрерывная интеграция и доставка): Настройка пайплайнов для автоматической сборки, тестирования и выгрузки обновлений. Инструменты: GitLab CI, Jenkins, GitHub Actions. Это минимизирует человеческий фактор при поставке.

Контейнеризация: Базовое понимание Docker. Это знание позволяет создавать воспроизводимые среды для разработки и тестирования (поднять чистый сервер 1С + БД за 5 минут).

Автоматическое тестирование: Инструменты вроде Vanessa Automation, xUnitFor1C. Вы должны выстраивать процесс так, чтобы регрессионные тесты запускались автоматически.

4. Смежные технологии для интеграций и расширений
1С редко существует в вакууме.

Веб-технологии: Понимание протоколов HTTP/HTTPS, REST API, SOAP, JSON/XML. Умение работать с Postman или аналогами для тестирования внешних API. Понимание основ OAuth/аутентификации.

Очереди сообщений (Message Brokers): RabbitMQ, Apache Kafka, Redis (как брокер). Ключевые концепции для построения надежных, асинхронных и слабосвязанных интеграций. Вы должны знать, когда использовать очередь, а когда достаточно веб-сервиса.

Мониторинг и логирование: Знание стека ELK (Elasticsearch, Logstash, Kibana) или аналогов (Grafana + Loki/Prometheus). Ваша цель — не ждать, пока пользователь пожалуется, а видеть проблемы на дашборде: рост времени отклика, ошибки в журнале регистрации, очередь заданий.

5. Общие принципы разработки и управления проектами
Архитектурные паттерны: MVC, SOLID, принципы чистой архитектуры. Понимание, что такое микросервисы и монолит, их плюсы и минусы. Это поможет вам проектировать модули внутри 1С и принимать решения о выносе логики вовне.

Проектный менеджмент: Методологии (Agile/Scrum, Kanban), инструменты (Jira, YouTrack). Вы должны управлять техническим бэклогом, оценивать трудозатраты, понимать жизненный цикл задачи.

Безопасность (Security): Не только "права в 1С". Понимание основ OWASP Top 10 (инъекции, XSS), безопасной настройки веб-серверов (TLS), хранения секретов (паролей, ключей API).

Как это интегрируется в работу техлида 1С?
|Ситуация|Знание без 1С|Ваше действие как техлида|
|-|--------|---|
|Клиент жалуется на "тормоза".|	Мониторинг инфраструктуры, анализ планов SQL-запросов.|	Не гадать, а запросить у сисадмина графики нагрузки на CPU/диск, проанализировать медленные запросы в БД и дать точную рекомендацию: "Добавить индекс" или "Увеличить память серверу".|
|Нужно сделать интеграцию с мобильным приложением.|	REST API, OAuth 2.0, очереди сообщений (RabbitMQ).|	Спроектировать не веб-сервис внутри 1С, а вынести логику в отдельный микросервис (на Python/Java), который через очередь будет асинхронно общаться с 1С, чтобы не нагружать основную систему.|
|Появилась задача по аудиту всех действий пользователей.|	Централизованное логирование (ELK-стек).|	Предложить не пихать всё в регистры сведений, а настроить выгрузку журнала регистрации в Elasticsearch для удобного поиска и дашбордов в Kibana.|
|Завтра инспекция, а данные критически важны.|	Стратегии резервного копирования и восстановления (RPO/RTO).|	Проверить не только наличие бэкапа БД 1С, но и всей цепочки: инфраструктуры, файлового хранилища, конфигураций. Провести учение по восстановлению.|

С чего начать изучение? План на 6 месяцев
Месяц 1-2: Git и CI/CD. Создайте репозиторий для своей конфигурации, настройте простой пайплайн, который при коммите будет делать выгрузку в файлы и собирать cf.

Месяц 3-4: Базы данных. Пройдите курс по оптимизации запросов в MS SQL/PostgreSQL. Научитесь уверенно читать execution plan.

Месяц 5: Инфраструктура. Разверните в виртуальной машине (VirtualBox) чистый Linux, установите на него Docker, поднимите в контейнерах PostgreSQL и сервер 1С. Это даст огромное понимание.

Месяц 6: Мониторинг. Установите Grafana и настройте дашборд для мониторинга базовых метрик вашего тестового сервера 1С (память, CPU, активные соединения с БД).

Этот путь сделает вас не просто специалистом по 1С, а полноценным инженером широкого профиля, способным проектировать и строить надежные, современные бизнес-системы.
